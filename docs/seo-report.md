# SEO report – Bubble Fiesta (igraonica-bubblefiesta.rs)

Scope: SEO, accessibility and performance only. Design, content and the booking flow were left unchanged. The only visual changes are the minimum colour adjustments needed for WCAG contrast, listed below.

## Lighthouse (mobile, Lighthouse 12.2.1)

Measured locally with Lighthouse's simulated slow 4G and a static server that does gzip and cache headers, like the `.htaccess` setup. "Before" is commit `f87f7c2` (the site as it was).

## What was changed

### On-page
- **Titles and descriptions:** unique on every page, all titles 45–56 characters and descriptions 136–145 characters. They cover the target keywords (pokretna igraonica, dvorci na naduvavanje, iznajmljivanje dvoraca, dečiji rođendan, krštenje, Bubble House, facepainting, animacija za decu, Tiffany sto i stolice).
- **H1:** exactly one per page. On the home page, the small handwritten tagline above the slogan now reads "Pokretna igraonica Bubble Fiesta" and is inside the H1, so the H1 starts with the main keyword and looks the same. Heading order is H1 → H2 → H3 on every page (footer headings are now `h2` styled as before).
- **Language:** `<html lang="sr">`, `og:locale` `sr_RS`.
- **Images:**
  - 16 photos renamed to descriptive Serbian file names (e.g. `beli-dvorac-sa-bazenom-i-lopticama-u-sali.jpg`).
  - Every photo now has WebP versions at 480, 800 and 1200 px, served with `<picture>` + `srcset`/`sizes` and a JPEG fallback.
  - All images have `width`/`height` and descriptive Serbian alt text.
  - Everything below the fold uses `loading="lazy"`; the hero image uses `fetchpriority="high"` and is preloaded.
  - `tools/optimize-images.py` regenerates the WebP versions.
- **Canonical** on every indexable page (`https://www.…`, no trailing slash, no `.html`).
- **sitemap.xml** (6 URLs), and **robots.txt** pointing to it, which also blocks the source folders.
- **Icons:** favicon.ico (16/32/48), favicon.svg, apple-touch-icon, 192/512 icons, `site.webmanifest`.
- **404 page:** custom `404.html` (`noindex`), with links to home, packages, booking and the cities.
- **Share image:** new 1200×630 image, `img/og/bubble-fiesta-pokretna-igraonica.jpg` (83 KB). All pages have Open Graph and Twitter Card tags, including `og:image:alt` and `twitter:image:alt`.

### Structured data (JSON-LD, generated by `tools/build.js`)
- **Home:** `WebSite`, `LocalBusiness` and `FAQPage`.
  - `LocalBusiness` includes name, url, telephone `+381 62 592 271`, logo, image, priceRange, the Instagram link (`sameAs`), and `areaServed` = Country Srbija + 10 cities.
  - Its `hasOfferCatalog` lists 3 `Offer`s (60/70/80 EUR, priced per hour with unit code `HUR`), each describing a `Service`.
  - The FAQ data is read from the visible FAQ on the page, so the two always match.
- **City pages:** `LocalBusiness` with `areaServed` = that City, plus `BreadcrumbList` and `FAQPage`.
- **/gde-dolazimo:** `BreadcrumbList` and `WebPage` (listing all towns under `mentions`).
- **Validation:** online validators (validator.schema.org, Google Rich Results Test) are blocked in the build environment, so validation was done offline:
  - Every type and property checked against the official Schema.org vocabulary v29.0: 223 nodes, **0 errors**.
  - `structured-data-testing-tool` (Google + social presets): **all tests pass**. The only warnings are about `twitter:site`, which needs an X/Twitter account.
  - All JSON-LD parses and the HTML passes `html-validate`.
  - **Re-run Google's Rich Results Test after deploying** (see checklist).
- **Note:** since 2023 Google shows FAQ rich results mainly for government and health sites. The markup is still valid and helps other search engines and AI assistants.

### City landing pages
- `/pokretna-igraonica-beograd`, `/pokretna-igraonica-novi-sad`, `/pokretna-igraonica-mladenovac`, `/pokretna-igraonica-smederevo`.
- Each has its own 3 paragraphs, its own venue list, a 4–5 question FAQ specific to that city, the 3 packages, and a booking section. City grammar is written by hand in `data/cities.json` (u Beogradu, u Novom Sadu, u Mladenovcu, u Smederevu).
- **Uniqueness:** after removing the city names, any two city texts share only 0–3% of their 5-word phrases (274–377 words per city). The build now fails if two cities share more than 25%, so copy-pasted city text can't slip in later. Tested with a copied city: it was rejected at 92%.
- `/gde-dolazimo` lists 51 more towns in 6 regions as plain text. There are no thin per-town pages.
- **Internal links** with descriptive anchor text ("Pokretna igraonica u Novom Sadu"):
  - home: a line under the packages, the FAQ answer "U kojim gradovima radite?", and a new "Gradovi" footer column;
  - all pages: the footer, the topbar ("Svi gradovi" → /gde-dolazimo) and the menu on inner pages;
  - city pages link to each other.
- **Booking from a city page:** the "Rezerviši" buttons open `/?grad=Beograd#rezervacija`, which pre-fills the city field in the existing form. The form, WhatsApp, Viber and Google Sheets flow are otherwise unchanged; an end-to-end test confirmed the WhatsApp message and price calculation.
- **Generator:** `node tools/build.js` builds the city pages, /gde-dolazimo, 404 and sitemap from `templates/` + `data/`, and injects JSON-LD and city links into `index.html`.
  - It also checks title/description length and uniqueness, one H1, heading order, alt/width/height, valid JSON-LD and broken internal links. The build fails if any check fails.

### Performance
- **Fonts:** self-hosted WOFF2 files (variable fonts, latin + latin-ext), `font-display: swap`. The 4 fonts used above the fold are preloaded. The Google Fonts request was removed.
- **Hero image:** preloaded with `imagesrcset`.
- **JavaScript:** `main.js` loads with `defer`. It now also works on pages without the form, gallery or video, instead of throwing errors.
- **Video poster:** now WebP (23 KB instead of 41 KB).
- **CSS:** no unused CSS of note; one file, about 7 KB gzipped. Inlining the CSS was tested and was slower (95 vs 96), so it stayed external.

### Accessibility (contrast and markup)
Decorative colours (blobs, icons, backgrounds) were left as they were. Only text and buttons that failed WCAG AA were darkened, by the smallest amount that passes:

### Server (`.htaccess`, tested on Apache 2.4.58)
- **Redirects:** HTTP → HTTPS and non-www → www in one 301. Works behind a proxy/Cloudflare via `X-Forwarded-Proto`.
- **Clean URLs:** `/index.html` → `/`, `/page.html` → `/page`, trailing slash removed; `/page` serves `page.html`.
- **Errors and privacy:** `ErrorDocument 404 /404.html` (custom page returned with status 404). `tools/`, `data/`, `templates/`, `docs/`, `google-apps-script/`, `README.md` and `.git` return 404.
- **Compression:** Brotli where the host supports it, otherwise gzip. Tested: with the `.htaccess` rules alone, Brotli is served. If the host's own global configuration already forces gzip, gzip is served, which is still fine.
- **Caching:** HTML `no-cache`; CSS/JS 1 month; images, fonts and video 1 year `immutable`.
- **Security headers:** `nosniff`, `Referrer-Policy`, `X-Frame-Options`, `Permissions-Policy`. HSTS is prepared but commented out; enable it once HTTPS works on both hosts.
